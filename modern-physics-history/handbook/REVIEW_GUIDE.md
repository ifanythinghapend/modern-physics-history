# 内容审阅指南

审阅从一条可以复查的陈述开始，例如一个日期、一项贡献归属、某实验排除的解释，或推导中的一步。记录“这一句在这些条件下由这份材料支持”，比记录“本章已验证”更有用。

编辑入口见 [CONTRIBUTING.md](../CONTRIBUTING.md)，行文安排见[编审大纲](../docs/outline.md)。核对记录保存在 [reviews/](reviews/)。

## 一、分清检查对象

| 范围 | 要回答的问题 | 不能据此声称的事 |
| --- | --- | --- |
| 书目与访问 | 作者、题名、版本、卷页、标识符是否正确？取得的是哪一版？ | 页面能打开，不能证明它支持正文。 |
| 历史 | 原始材料和专业研究怎样说明时间、归属与语境？ | 一篇获奖介绍，不能独自解决复杂优先权争议。 |
| 物理解释 | 模型对象、实验条件、可观测量和结论范围是否对应？ | 模型拟合成功，不等于排除了所有其他解释。 |
| 数学推导 | 定义、假设、每步运算及所用定理是否足够？ | 公式量纲正确，不等于推导正确。 |
| 行文 | 问题是否推进，解释是否重复，前后是否接得上？ | 叙述流畅，不等于史实与理论已经核实。 |
| 工程 | 编号、内部链接、生成物和公式排版是否一致？ | 自动检查通过，不等于内容通过学术审阅。 |

不要求每次修改完成全部范围。修正错字可以只做行文检查；修改核心公式则须检查使用该式的后续推论。审阅记录列出实际完成的部分。

## 二、怎样留下可复查的证据

重要论断的记录包含以下内容：

1. **对象**：文件、小节锚点、原句或公式。不能只写“量子论一章”。
2. **版本**：Git 提交号；尚未建立 Git 仓库时，记录源文件 SHA-256。涉及多个文件时分别记录。审阅日期与材料截止日期分开。
3. **来源**：既有文献编号、完整书目信息、所用版本与访问入口。原刊、译本和后来的重印本分清。
4. **位置**：原刊页码、章节或公式号；使用 PDF 页码时注明这是文件页码。网页无页码时写标题、段落主题及检索关键词。
5. **支持范围**：来源实际支持什么、不能据此推出什么。必要时列出另一来源提供的不同解释。
6. **处理结果**：保留、改写、删除或待补证，说明理由，并登记尚未解决的问题。

原句较短时可直接摘录，长段用准确转述和定位。不要把整篇论文复制进仓库。来源有多个访问地址时，保留作品身份，分别记录原刊、译文或存档地址；临时访问失败不立即更换文献号。

提交号和摘要确定“审了哪份文本”，不能证明审阅质量。脚本或辅助工具参与核查时说明其实际作用；不得由生成了记录就声称已经获得独立专业审阅。

## 三、状态与交叉审阅

每份记录使用以下状态，并说明适用范围：

- **待核对**：已列出问题，尚无足够证据和核对结论。
- **核对中**：已核对部分陈述，仍有待查或待交叉审阅项目。
- **本版本已审阅**：所列范围已完成自查与交叉审阅，记录版本、依据及仍不包括的内容。这个状态不扩展到整章或全书。

完成作者自查后，将证据与修改交给另一位具备相应知识的审阅者。暂时没有合适人选时，可以发布有明确限制说明的讨论稿，保留“核对中”和待交叉审阅事项。维护者负责确认修改入口、记录范围及发布物一致，不自动承担每个分支的专家认证。

合并后发现错误，补充更正和受影响的结论。源文件发生实质变化时，旧记录作为历史保留，将当前相关条目标为需复核。摘要改变也可能只是标点调整；核对差异后才能判断是否需要重审数学或史实，不能只凭摘要不同就推翻全部旧结论。

## 四、史实与实验的重点

分别核对事件发生、报告、投稿、发表、独立验证和授奖时间。时间轴引用次年论文不一定错误，但应能在来源中定位它所记述的前一年事件。人名归属具体到提出、推导、测量、解释或实现，不把其中一个动作扩张为整项发现。

遇到“首次”“证明了”“解决了”“唯一”等强断言，核对限定条件和可能遗漏的先行工作。不同来源冲突时，先分清它们是否在谈不同事件或不同含义；仍无法排除争议时，在正文缩小表述或说明争议。

实验部分写清测到了什么、比较了哪些模型、在什么精度与条件下支持结论。时效性陈述注明资料日期，避免用较早综述支撑“目前所有”“最新纪录”这样的判断。

现代重构的推导只代表一种教学组织方式。若进一步讨论它与原作者思路的关系，历史说明需要自己的出处，不能由两种写法得到同一公式就推定发现过程相同。

## 五、推导的最少说明

短推导在源文件中使用加粗小标题，保持现有包含和标题层级规则。根据内容安排以下说明，不强迫每则拆成六个等长段落：

- **计算对象与记号**：要求什么量；变量、单位、正负号和常数约定是什么。
- **假设与范围**：模型、平衡或非平衡条件、边界条件、系综及允许的参数区间。
- **近似**：哪一步舍去了什么，何种极限下合理；与纯粹的定义和基准选择分开。
- **计算**：写出容易影响理解的中间步骤，注明换序、极限、求导或定理的条件。
- **检查与边界**：量纲、符号、已知极限及可能失效的情形；没有可用检查时如实说明。
- **历史说明与出处**：区分现代重构和原始论证，各自给出适当材料。

只增加与当前结论有关的步骤。若展开后掩盖正文主线，保留关键计算并把长证明另行组织；不得用“显然”隐藏真正需要解释的条件。

## 六、普通 Markdown 记录格式

下面是填写次序，实际记录应写入具体内容；没有完成的项目注明“待核对”，不要保留空栏冒充已审阅。

```text
题目：所核小节或论断
对象：源文件与小节锚点
版本：提交号，或每个相关源文件的 SHA-256
日期：本次核对日期；另列时效性材料的截止日期
范围：实际检查的维度
状态：待核对 / 核对中 / 本版本已审阅

逐项记录：
  原句或公式
  文献编号、完整书目信息与版本
  页码、章节或公式号
  支持范围与限制
  核对结果和所作修改

交叉审阅：是否完成，检查范围与意见
未决事项：缺失证据、待复核步骤、未覆盖部分
```

不要求填写真实姓名、私人联系方式或个人学习经历。需要区分贡献者时只用经本人同意的公开标识。一次小修可将完整记录直接写在 PR 中；需要长期追踪或涉及争议的结论，再保存到 `handbook/reviews/`，避免重复维护。

## 七、合并与发布检查

先确认文字修改与证据对应，再运行结构与构建检查，最后查看生成后的公式、引用跳转和改动段落。技术步骤见 [BUILD.md](BUILD.md)。

外链探测中的限流、拒绝访问和超时属于无法判定。确认失效的地址可增加可靠替代入口；如果来源内容尚未取得，就如实保留待查。不能为使检查全绿而删掉仍有必要的引用。

发布说明分别写清内容改动、已经完成的审阅范围和仍待核对的部分。网页、合并稿和 PDF 同步重建时核对版本文字；保留旧 PDF 时须明确其内容版本，不能只修改文件名或封面日期制造同步假象。
