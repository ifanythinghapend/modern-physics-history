# 勘误与修改

请围绕具体问题提出修改：哪里需要改，为什么要改，有什么可以查证的依据。讨论与协作遵守 [CODE_OF_CONDUCT.md](CODE_OF_CONDUCT.md)。项目目标与编写约定见[项目纲领](handbook/PROJECT_CHARTER.md)，章节主线见[编审大纲](docs/outline.md)，核对方法见[审阅指南](handbook/REVIEW_GUIDE.md)。

## 提出勘误或资料建议

在 Issues 中选择相应模板，填写：

- 章节、小节、原句；用 PDF 页码时注明版本。
- 问题与建议，或需要补充的推导步骤。
- 支持建议的作者、标题、年份、DOI / 链接，必要时附页码。

新章节建议还应说明要回答的问题、与现有章节的关系及已有资料。推导请求请指出从哪一步到哪一步读不通、已知哪些前提、希望补到什么程度；可选用“推导补充”模板。讨论以论证和证据为准，不要求所有建议都被采纳。

## 修改哪个文件

| 要修改什么 | 位置 |
| --- | --- |
| 导读 | `docs/preface.md` |
| 正文 | `docs/chapters/` |
| 推导 | `docs/derivations/` 下的编号文件 |
| 时间轴、文献及问题索引 | `docs/appendices/` |
| 标题、顺序、新增章节或推导的登记 | `data/book.json` |
| 章节主线、衔接和材料取舍 | `docs/outline.md` |
| 具体论断的长期核对记录 | `handbook/reviews/` |

`manuscript.md`、`index.html`、三份索引 JSON、BibTeX 和推导目录均由程序生成，不要把它们当作第二份编辑源。章节中的 `include-derivation` 标记决定推导插入的位置；保留这些标记，修改对应推导文件即可。短推导继续在阅读版原位呈现。当前程序不解析章节 YAML 状态或 `[@key]` 引文；不要直接向正文加入这些语法。

保留既有章节、问题和文献锚点。新增条目使用未占用的编号；不要为了排列整齐而更改旧文献编号。跨文件链接使用相对路径与目标锚点。

## 怎样核对

史实优先查原论文、档案、专业研究和实验合作组资料。发现、发表、观测与获奖时间分别核对。存在优先权争议或多条独立路线时，说明证据与差异。

推导须交代变量、假设、边界条件、近似及结论范围。现代记号下的重构，不应被写成当年原作者的发现过程。已证结论、实验支持、模型预测与开放问题分开表述。推导内部使用加粗小标题，保持现有嵌入层级；增加中间步骤时一并检查量纲、符号和适用的极限。

正文资料链接登记在附录 D；第 1—19 章核心问题的引用对应关系写在附录 E。新增或更换引用时，一并核对这两个附录。JSON 和 BibTeX 从附录导出，其中 BibTeX 使用 `@misc` 保存原资料短标签、网址和类型，并非完整的作者—题名—期刊书目。

对重要史实、核心公式或有争议的解释，写明原句、来源页码或公式号、来源实际支持的范围，以及被审源文件的提交号或摘要。小修可写在 PR 中，需长期追踪的内容保存在 `handbook/reviews/`。链接可达与自动检查通过都不能代替这一核对。

## 提交修改

一次修改围绕一个清楚的问题，在 Pull request 中说明原因、改动及核对依据。先做作者自查，核心论断再请另一位具备相应知识的贡献者交叉审阅，最后由维护者合并。尚无合适审阅者时，保留待交叉审阅说明，不能标记为整章已核验。提出勘误、修正错字或提交纯文字修改不要求安装排版环境；GitHub 自动检查会读取源文件并构建网页。

审阅状态限定到具体版本和范围，使用“待核对”“核对中”“本版本已审阅”。实质修改须复核相关旧记录及后续结论；标点等文字改动由审阅者检查差异后判断是否影响已有结论，不必每次重审全章。

维护者在合并及发布时更新生成文件：

```bash
python scripts/build_web.py
python scripts/check_package.py
```

安装依赖及更新 PDF 的方法见 [handbook/BUILD.md](handbook/BUILD.md)。若仅在线修改，可从 **Actions → Check and build → Artifacts** 下载新生成文件，核对后更新仓库中的相应快照；工作流不会自动提交。

## 行文与来源

用问题带出研究工作，避免把姓名、年份和术语堆成条目。补充一段材料时，说明它如何接上前文，又改变了什么问题。段落之间要有实际联系，不用空泛的意义评述代替解释。

不要提交无权公开的材料或私人信息。大段新增内容合并前，应确认来源与使用条件；项目当前许可状态见 [LICENSE_STATUS.md](LICENSE_STATUS.md)。
